模型不断升级变得越来越强，吃掉更多 token。我最常被问到的问题变成了两个：为什么别人都很省？我的 Codex 月费套餐怎么总是不够用？

很多人以为把 Prompt 写短一点就能省额度。但真正吃掉你额度的，从来都不是你打的那几个字。

你送出的可能只有短短 50 个 token；但在背后模型实际处理的输入量可能高达 **100,050 个 token**。

多出来的那十万，全是你在这个 session（聊天窗口）里累积下来的历史记录。

每一次你按下 Enter，都会把它们原封不动重新送给 AI 读一遍。

坦白说，AI 花了多少钱，我并不太在意。但我一直在想办法省 token。

因为省 token 带给我的价值不只是钱，而是清掉那些没用的噪音之后，更干净的环境context，模型就能拿到更完整的注意力——而这份注意力长期下来会决定你的 Agent 产出什么质量，自然干活效率就更高。

所以对我来说，省 token 逼着我定期 review AI 时代留下的技术债——这已经变成一个必须养成的习惯了。

这篇文章就是要从底层机制出发，教你怎么精准控制每一次送出的 Context，怎么给你的 Agent 更干净的 Context。

让你在同样的订阅方案下，省下更多额度，同时还能拿到更好的输出。

## 你按下 Enter 的那一刻，背后到底叠了哪四层东西？

每次你在对话框打完字、按下 Enter，你以为自己只送出了一句话。但如果把这通 API 请求拆开来看，底层其实整整叠了四层东西：
![1022-额度文-每次都当第一次-动图](http://tmyjqo2lv.hb-bkt.clouddn.com/wx/10/22/0151-261.gif?e=9000000000&token=6KzDwEy-FNdz0ng24Umd2wNTnNuYgUcAjBPObD7r:qlCA-NZ0X07xQzUEyDGvHUFjBus=)

1. **第一层：系统与项目规则**
    

包括：像 Claude Code、Codex 这类工具内置的系统提示词（System Prompt），以及你放在项目根目录的 `CLAUDE.md` 或 `AGENTS.md`。

还有目前的 Git 分支状态、操作系统环境、工作目录路径。

这一层你平常在对话框完全看不到。但每一次送出，它都默默跟在最前面。

1. **第二层：工具清单与使用说明**
    

你挂载的每一个工具，包含内置的终端、读写文件、搜索功能，还有你外接的每一个 MCP Server。

它们的工具名称、用途说明、参数格式，每一轮都要被完整打包送进去。

1. **第三层：完整的对话历史**
    

你在这个窗口里聊过的每一句话、AI 回复给你的每一段长篇分析、它写出来的每一行代码。

1. **第四层：外部文件与工具的执行记录**
    

你让 AI 读过的上千行原始代码、爬下来的网页或 PDF 内容，以及它在终端跑测试时喷出来的那一大串错误日志（Log）。

![1022-额度文-四层请求构成-动图](http://tmyjqo2lv.hb-bkt.clouddn.com/wx/10/22/0151-ff3.gif?e=9000000000&token=6KzDwEy-FNdz0ng24Umd2wNTnNuYgUcAjBPObD7r:2tH4-Sbp7nIoM8mlqYQrCarUgeE=)

为什么这四层每一轮都非得重送不可？原因很单纯：**底层的大语言模型（LLM）本身是完全没有记忆的。** 模型根本不记得上一秒跟你们聊了什么。

我们之所以觉得它「记得」，是因为每一次对话，软件都把整段历史记录原封不动重新塞回输入端，让它从头读一遍换来的。



雪球就是这样滚起来的。

第一轮对话时，历史记录是空的；到了第二十轮，前面产生的长篇分析、读进来的文件、跑出来的 Log，全都会变成历史的一部分，重新塞回它的肚子里。

你打的那几个字，可能连整包请求的 1% 都不到。

### 关键观念：旧信息不等于无用垃圾

过去聊过的旧内容，不代表全部都是浪费。

已经敲定的系统架构、修改过的文件清单、还在报错的测试，以及排除方案的理由，这些会影响下一步决策的有效状态要留下。

真正该清掉的是任务已结束、也不会再影响后续决策的过期产物，例如登录成功之后就再也不需要的一整页网页、被淘汰的草稿、已修好的测试日志。

判断只要问两个问题：这项信息还会改变接下来的任何决定吗？如果拿掉会不会逼 AI 重做已经验证过的工作？两个问题答案都是不会，就清掉。

处理 Token 的黄金顺序：**能丢就丢 ➔ 能缩就缩 ➔ 最后才靠缓存打折**。

丢掉的成本是 0；缩小只付精简后的量；缓存只让单价便宜，发送的 Token 总量没有少。

### 第一个动作：能丢就丢

只要下一次对话完全用不到，就让它消失在这个窗口里。

换任务就果断开新对话；指令走偏时善用回头编辑与回溯；关掉当前任务用不到的工具与 MCP。

用 `/rewind` 回到已知路口通常比 `/compact` 更省。

### 第二个动作：留下来的，缩到最小

先搜索再喂给模型，只提供最相关段落。

只需要文字就别丢截图或整份文件；只输出修改的段落，不要重写整篇。

交接时只带走拍板决定、有效事实、未解问题、改动文件和明确禁区。

### 第三个动作：剩下的才去打折

缓存会把前缀重复内容的价格降低，但第一次写入通常较贵；只有接下来几轮会反复用到的信息才值得放进缓存。

换模型、改思考强度、进出 Plan Mode、升级工具或执行 /compact，都可能让缓存失效。

## 有些请求，其实根本不需要存在

输入格式固定、转换规则明确、对错标准也定下来的工作，例如排序、计算、日期转换、JSON 互转和精准搜索，直接写成代码或本地脚本就好。

不必每次重新调用模型。

## 结语：每一次按下 Enter，你买单的是整串脉络

不用提供的信息就丢掉，一定要提供的信息浓缩，到最后才用缓存。

面对任何信息，问「这项信息还会改变接下来的决定吗？」以及「拿掉它会不会逼 AI 重做已完成的工作？」

省 Token 的终极目的不是省钱，是确保送进去的每份 Context 都值得 AI 认真读。
